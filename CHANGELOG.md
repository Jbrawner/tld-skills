# Changelog

All notable changes to Adventure Skills are recorded here. Versions follow semantic versioning once we leave alpha.

## [Unreleased]

### Added

- `/docs-drift-audit` skill — a recurring documentation-versus-code check, built on the same engine-plus-baseline shape as `/rls-audit` and aimed at a different silent failure: documentation does not break loudly. A wrong price in a sales deck, a link to a file that was renamed, a schema table naming a database table that has been empty for a month — none of it turns anything red, so it survives until somebody acts on it, and by then that somebody is a customer or an agent rather than the author. The engine is one project-neutral Python file with a stdlib-only dependency set, read-only on code and on the documents themselves, and it sweeps document roots that may sit **outside** the repository entirely, because product documentation usually lives in a synced drive folder rather than in `docs/`. Six checks: an anchor whose stated value the code contradicts, an anchor whose pattern no longer matches anything (reported at HIGH as a **check gone inert**, never as a pass, which is the failure the whole design is arranged around), a baseline-named document that has left the swept set, a file path or link that resolves nowhere, a retired route or product name a document still tells readers to use, and a document whose watched code moved on well after it did. **Noise is what kills a recurring documentation check**, more so than a security one, because prose generates false positives that SQL does not: every row is labelled `NEW` or `KNOWN-OPEN <KEY>`, reviewed-safe exceptions live on an allowlist that requires a written reason per entry, and the heuristic checks over-flag on purpose with the benign shapes documented in the skill so triage is a lookup rather than an investigation. Two of those shapes are worth naming because they are counter-intuitive: a document that mentions a retired table *in order to say it is retired* must not be flagged, since the fix would delete the one sentence stopping the next reader from using it; and a whole family of unresolvable paths usually means the project writes paths from inside a subtree, which is one `path_search_roots` entry rather than fifty allowlist rows. Filing is the default rather than an offer, de-duplicated first against open tickets carrying the skill's own stable label and matched on **affected object identity** (document, anchor id, path, term) rather than ticket title, with an object appearing only on a *closed* ticket filed as a regression — the proving run produced exactly that, finding the `$29/$99` pricing a closed ticket had been closed for, still sitting in the repository's own architecture overview four months later. Never capped: no top-N, no sampling, findings sharing one root cause folded into a single ticket, and anything left out named explicitly. **Nothing time-bound anywhere**, written into the skill as a rule so a later edit cannot reintroduce it: a dated label on ticket output is fine because it is built from the real date at run time, but a date inside a lookup that has to keep matching is a check that stops matching without ever reporting that it stopped. Fails safe — an unreachable document root or an unrunnable anchor command is a SKIPPED row and a `PARTIAL` run status, never a silent green, and a missing repository or a named-but-absent baseline exits NOT-RUN rather than reporting a clean sweep of nothing. It degrades rather than fails: with no baseline at all it discovers a `docs/` directory, runs the path check, and reports everything as new. Deliberately does **not** embed three canonical blocks: **Load project config**, because it hard-stops on a missing `.tld/campaign.md` and this skill has to run in repos that have none, resolving tracker settings from its own baseline instead; **Local DB safety check**, because there is no database in scope; and the **approval keyword set**, because filing is the default and there is no gate for a keyword to open.

- `/rls-audit` skill — a recurring row-level-security and SECURITY DEFINER posture check that reads the **live local database** rather than a diff. It exists because of a failure mode `/tld-audit` structurally cannot catch: `CREATE OR REPLACE FUNCTION` resets a function's grants, so a control that was correct the day it was written can be silently reverted months later by an unrelated migration, with no diff anywhere that looks wrong. The sweep that motivated this found exactly that — ten internal helpers handed back to `anon`, two of which returned cross-tenant data by UUID with no auth check at all, from a revoke that named `PUBLIC` while the grants were held by `anon` and `authenticated` by name. The two skills are complements, not duplicates: tld-audit reads the change, rls-audit reads the state. Seven checks run against the system catalogs: tables with RLS disabled, DEFINER functions without a pinned `search_path`, INSERT/UPDATE/ALL policies with no `WITH CHECK`, data-returning DEFINER helpers reachable by a client role that never authenticate, the boolean/void variant of the same, policies whose `USING` is literally `true` for a client role, and data RPCs matching the project's reporting convention that are anon-reachable or unauthenticated. **The design problem with any recurring security check is noise** — a report that reprints the same known findings every week stops being read, and a real finding then hides inside the list — so every row is labelled `NEW` or `KNOWN-OPEN <KEY>` against the ticket tracking it, and confirmed-safe exceptions live on a reviewed allowlist that requires reading the function before a name goes on it. Findings are filed to the tracker automatically rather than offered, because the skill is built to run unattended and a finding that lives only in a transcript is a finding nobody found; a de-dup pass first matches open `rls-audit` tickets on the **affected object name** rather than the title, so an unfixed hole does not collect a new ticket every run, and an object that appears only on a *closed* ticket is filed as a regression, which is the most valuable signal the sweep produces. Filing is never capped: no top-N, no sampling, no stopping once the list gets long, because a truncated security report is indistinguishable from a complete one and the gap is therefore invisible, so findings sharing one root cause are folded into a single ticket rather than dropped, and anything left out for any reason at all is named explicitly in the report. The one guard the engine infers on its own is an in-body `auth.uid()`; naming a permission helper is explicitly not enough, because a body calling `is_member(auth.uid(), x)` already counts as guarded, so any "treat these helpers as a guard" shortcut could only ever excuse `is_member(<caller-supplied arg>, x)`, which is no guard at all when an anonymous caller can pass somebody else's id, and it would turn the riskiest shape into a clean pass. Project-agnostic: the engine is one SQL file identical everywhere, and everything project-specific (schemas, client role names, reporting-RPC pattern, accepted exceptions, known-open findings, tracker) lives in a committed per-repo baseline resolved from `.tld/`, `.claude/`, or the repo root, since a repo that gitignores `.tld/` would otherwise carry an uncommitted baseline that forgets every reviewed exception between runs, with `baseline.example.sql` as the template. It degrades rather than fails: with no baseline the sweep still runs and reports everything as new, roles that do not exist in the database are ignored so plain Postgres projects work, and a repo with no tracker configured reports in full instead of guessing where to file. Deliberately does **not** embed the canonical Local DB safety check: that block resolves `Stack.Database` from `.tld/campaign.md` and exists to gate destructive operations, whereas this skill is read-only, must work in repos with no campaign file, and applies a flat loopback-only refusal instead, which is the stricter rule.
- `/tld-autoland` skill — the first and only TLD skill that merges into the default branch. Takes one small bug-fix ticket, or a chunk of them (`/tld-autoland AS-31 AS-32 AS-33`, or a Story key that expands to its children in tracker order), and drives each one end-to-end with no stops: eligibility gate → fresh branch cut from the freshly-pulled default → `/tld-full-auto` → changelog → commit → mark Done → push → open PR → watch CI → squash-merge → delete branch → back to the default branch → next ticket. One branch and one PR per ticket, so tickets never stack and a parked one never blocks the rest. Every other skill in the family stops at a verified checkpoint or an open PR by design; autoland exists for the narrow category where a review gate costs more than it protects — bug fixes you would approve without reading the diff. Because the merge gate is gone, the safety model moves from *stops* to *admission*: a ticket needs the new `auto-land` label to enter (no override flag, no approval keyword), protected surfaces are refused on both the ticket text and the realized diff, and the merge fires only on a positively-confirmed green CI result. Red checks, checks still running at the 20-minute watch ceiling, merge conflicts, required reviews, and any state that cannot be confirmed all park instead of merging — "I could not tell" is treated identically to "it failed," and auto-merge is deliberately never enabled as a consolation because an unattended merge that is never reported is the outcome the skill is built to prevent. Failures park rather than cascade: the work is committed and pushed to the ticket's own branch, the reason is posted to the ticket, the ticket is returned to Todo so exactly one is In Progress at a time (a parked ticket left In Progress makes the *next* ticket's "In Progress and assigned to me" resolution ambiguous and stalls the run), a clean default branch is restored, and the run continues to the next candidate. Nothing in the skill discards work — there is no `git reset --hard`, `checkout -- .`, `stash drop`, or `clean` on any path. A `skip`-command campaign aborts the run outright, since a merge gated on "tests green" needs tests. The final report accounts for every candidate as merged, parked, or skipped, with the diff stat and the exact resume command for anything that needs a human.
- `auto-land` workspace label (`#0EA5E9`), raising the required label set from eight to nine. It is the sole eligibility gate for `/tld-autoland` and is registered rather than left implicit for the reason recorded in the `no-tests` fix below: on Linear a label must exist in the workspace before it can be applied, so an unregistered routing key makes its path silently unreachable. Deliberately has no accepted synonym — `no-tests` accepts `build-only`, but a flow that merges into the default branch should match one exact string and nothing else. A typo fails safe (the ticket is skipped as unlabeled, never merged). Added to every reader: STANDARDS.md's canonical table and both embedders (`campaign-init`, `campaign-test`, including its Linear check list and Jira JQL audit), `campaign-validate`, README, docs/ADAPTERS.md, and docs/JIRA.md — whose routing-label note now covers both keys and their opposite failure directions.

### Changed

- `/tld-ticket` now sizes every ticket it creates. Step 4 collects a third value alongside model and effort — a point estimate — and step 6 writes it to the ticket's point field (Linear `estimate`; Jira Story Points). Points here measure **agent burn**, not human time: one point is roughly ten minutes of a single agent working the ticket alone, scaling with complexity and token cost, which is the unit that actually models throughput when the work is done by agents rather than people. Because the pipeline already decomposes work into uniform agent-sized units, the rubric biases hard to **1** — almost every sub-task `/tld-ticket` creates is a 1, a 2 is genuinely heavier work that still fits one ticket, and a 3 is usually a signal to split into pt-1 units instead (pointing at Template Rule 5, "one ticket = one thing"). Anything above 3 is Story- or Epic-sized and is handed back as a split rather than created. The skill proposes a size with a one-line rationale rather than defaulting blindly, offers the neighbouring sizes, shows the pick in the step 5 preview next to the labels, and falls back to `sonnet` + `medium` + 1 point if the prompt is dismissed. Writing the size is deliberately non-fatal: the point value is metadata while the AC, files, labels, and parent link are the payload, so a rejected write is reported and the ticket still lands.
- docs/JIRA.md gains a **Story Points (point estimates)** section covering why the Jira path needs the graceful-degradation rule above. Three facts drive it: the field id is per-instance (`customfield_10016` on many sites, not all, and some carry a legacy `Story point estimate` alongside it), so it must be resolved at call time via `getJiraIssueTypeMetaWithFields` and matched by name instead of hard-coded; the field is screen-scoped, and the usual failure on a TLD campaign is not a wrong id but Story Points being configured for Story and Epic while the work is created as **Sub-tasks**; and fixing that is a Jira project-configuration change to screens, which no skill can do at runtime. Fills the gap that made `/tld-ticket`'s new pointer to this doc a dead reference.
- `/tld-goal-handoff` now composes a **multi-Story, self-landing goal by default** instead of a single-Story goal that stopped short of a PR. No-argument runs hand off EVERY Story that still has an unfinished Sub-task, in rank order; one or more Story keys narrow the run to those Stories; a Sub-task key still composes the single-ticket goal, now via a dedicated §4b variant with NO PR gate (a mid-Story landing's PR belongs to its Story mark, not to the ticket). Each Story runs on its own branch `story/{KEY}-{slug}` cut from `origin/{default}` (worktree-safe, the same trick `/tld-autoland` uses) and ends at a **PR gate at the Story mark**: `/tld-gate` → full local suite → push → `gh pr create` → `gh pr checks --watch` with at most 3 fix-commit-push rounds on red, under a "fix the code, never the gate" rule (no editing workflows or weakening tests to force green) → `gh pr merge --squash` → confirm `MERGED` state → Story marked Done only when every Sub-task is → next Story cut from the freshly-updated default. The goal text itself carries the explicit push/PR/merge authorization, and the merge lane mirrors autoland's discipline — merge only on positively-confirmed green, "cannot tell" treated as "failed" — with one addition: a failed Story mark parks the Story (PR stays open, work pushed, reason logged) and then makes a dependency judgment, because later Stories are cut from a `{default}` that will NOT contain the parked work — Stories independent of it continue, dependent ones are skipped with a note, and the run stops entirely only when everything left depends on the parked Story. Blocked tickets still skip-and-continue within their Story. What makes "unlimited Stories" fit the 4000-character `/goal` cap: the block lists Stories, not tickets — the runner resolves each Story's unfinished Sub-tasks from Jira by rank at runtime, so the block grows ~25–35 characters per Story instead of per ticket. The rewritten scaffolding measures ~3,210 in a typical run (~3,420 with every braced clause present), leaving roughly 780 characters for the Story list, and the trim table gains a final unbounded lever: split the run into two handoffs — each Story merges at its own mark, so nothing is lost by splitting. Compose-time additions in support: a landing preflight (`gh auth status`; squash allowed and permission ≥ write via `gh repo view` — STOP with the exact remediation rather than composing a goal that dies at its first Story mark), a separately-captured Story done-transition id (Story workflows can differ from Sub-task ones), and a merge-lane guard refusing multi-Story handoffs on campaigns with no runnable test command, for the same reason `/tld-autoland` aborts skip-campaigns: no test signal to gate a merge on. Per-ticket `no-tests` labels inside a tested campaign remain fine — those tickets ride `/tld-full-auto`'s label-gated path, land with the ` — NPC` suffix, and the Story still merges on the campaign's real suite plus CI.
- Documentation now describes three routes instead of two. README's flow table gains a **TLD no-tests path** column (pipeline, what "tests" means there, what the drift check does and does not flag, trigger condition, and which skills drive it), notes that NPC refuses campaigns with a real test command, and drops the stale "same Linear tracker" framing for "Linear or Jira". `/tld-help`'s Automation table gains a row for the label-gated `/tld-full-auto` path and flags the new NPC refusal on both NPC rows. Follow-up to AS-4: the routing existed but nothing user-facing told you about it.
- The canonical "Require current ticket (strict)" block (STANDARDS.md) gains a leading **Case A0 — same-session setup context**: when the session already ran a formal `/tld-setup` whose output carries the active ticket (ID, AC, Files to Create/Modify) and nothing since indicates the ticket changed (no `/tld-next`, `/tld-skip`, `/tld-cancel`, no user statement to the contrary), phase skills use that in-conversation context and skip the redundant tracker query — cutting roughly four tracker round-trips per aggregator-driven ticket. Standalone runs without that context fall through to the existing Case A/B/C untouched. Propagated byte-identically to all ten embedders (`tld-align`, `tld-build`, `tld-commit`, `tld-partial-auto`, `tld-pr`, `tld-run-test`, `tld-skip`, `tld-write-tests`, `npc-full`, `npc-partial`); the cancel variant is deliberately unchanged since canceling may target a ticket other than the session's active one. Generalizes `tld-audit` §1's conversation-context-first pattern. (AS-10)
- `/npc-full` and `/npc-partial` now refuse campaigns with a runnable test suite (new §1a guard): before invoking `/tld-build` they resolve the test command exactly as `tld-build` step 1b does, and if it resolves to a real command (not blank, not the literal `skip`, not an `echo`-style SKIP placeholder) they stop and point to `/tld-run-test`, `/tld-partial-auto`, or a `no-tests`-labeled ticket via `/tld-full-auto`. No override keyword. Skip-style campaigns behave exactly as before. (AS-9)
- `/tld-full-auto` and `/tld-partial-auto` now claim (self-assign) the active ticket right after setup identifies it, mirroring `/tld-orchestrate` §4: unassigned tickets are assigned to the current user (Jira `editJiraIssue`/`assignJiraIssue` with the `atlassianUserInfo` accountId; Linear `save_issue`), tickets already assigned to the current user are left alone, and a ticket assigned to someone else is a STOP (claimed by another person, per docs/JIRA.md § Concurrency). Without the claim, the next phase's "In Progress AND assigned to me" resolution found zero tickets on unassigned Jira sub-tasks and broke the chain mid-run. (AS-8)
- `/tld-goal-handoff` now composes flow-aware goals instead of prescribing `/tld-full-auto` for every ticket: step 2 classifies each ticket (`full-auto` / `no-tests` / `migration`, migration wins ties), step 4's ordered list tags every entry like `AS-12 (title) [no-tests]`, the goal template tells the runner that a `[no-tests]` checkpoint reads "regression-clean, NOT spec-verified" (riding `/tld-full-auto`'s new label-gated path), campaigns with no runnable test command swap in a direct `/tld-setup` → `/tld-build` → AC-self-review method, and the landing step states the commit-suffix rules (` — TLD verified` for test-verified landings, ` — NPC` for no-test landings). Step 1 also gains a tracker guard: non-Jira campaigns stop with "tld-goal-handoff currently supports Jira only" instead of silently proceeding. (AS-7)
- `/tld-full-auto` now takes tickets labeled `no-tests` or `build-only` through a label-gated **no-tests path** instead of dying at stop condition 7: the RED phase (`/tld-write-tests`) is skipped by design (an explicit, reported skip), `/tld-build` green means the implementation is authored with no new-test requirement, and `/tld-run-test` verifies as a REGRESSION gate (existing suite must stay green; absence of new tests is not a failure and not AC-coverage drift) plus the usual file-scope drift check and manual QA plan. Mirrors the existing migration re-check pattern; if a ticket is both migration and labeled, the migration classification wins. Unlabeled tickets behave exactly as before. (AS-6)

### Fixed

- `/tld-goal-handoff`'s closing block is condensed so the 4000-character gate is actually satisfiable, and the trim table's scaffolding figure is corrected to a measured number. Two things had gone wrong. First, the gate was not reaching anyone: the installed checkout was parked on a feature branch 25 commits behind `main`, so every run loaded the pre-fix skill whose rule 2 still read "under ~4000 characters" with no measurement step, and a 4,204-character `/goal` block shipped with its own count printed beside it. Fast-forwarding the checkout restored the `wc -m` gate next to a local `/tld-gate` + E2E ending that had only ever existed uncommitted. Second, the two halves together no longer fit: that ending measured 719 characters of fixed scaffolding, putting the template at 3,417 in a typical run and leaving 583 for the ticket list and every substituted value, so a 12-ticket Story rendered at 4,035 and the restored gate would have demanded a Story split on a Story that did not need one. The ending is rewritten to 363 characters with every requirement intact (run `/tld-gate` and do not call the run good until it passes; run the full E2E suite to completion before any PR push and never push a red or unfinished E2E; write the wake-up report and stop), which brings the typical template to 3,061 and headroom to 939. The same 12-ticket Story now renders at 3,679, measured. The trim table's "~2,800 characters" figure, recorded in the entry below and invalidated by the merge, is updated to the measured ~3,050 typical and ~3,300 with every braced bullet still present.
- `/tld-goal-handoff`'s 4000-character cap on the `/goal` block is now a hard, measured, pre-print gate instead of a suggestion counted after the fact. Three defects let an over-cap block ship: hard rule 3 read "under **~4000** characters" (the tilde makes 4,300 arguable when the real behavior is that `/goal` does not run at all), step 5's pre-print self-check had four rows and length was not one of them, and step 6 asked for the character count *after* the block was already printed — so the count served as a confession rather than a gate. Rule 3 now states the hard limit and defers measurement to step 5; step 5 gains a fifth check requiring a measured count with an explicit `wc -m` on a scratch file (an eyeballed count is not a measurement, and is exactly how a 4,300-character block ships with "4,300 characters" written next to it); step 6 reframes the printed count as a receipt for a check that already passed. The old trim advice ("condense ticket titles first") was also actively misleading — the fixed template scaffolding measures ~2,800 characters before a single ticket is listed, so titles are a ~10–20-character-per-ticket lever against a several-hundred-character overflow. It is replaced by a trim order ranked by real cost (drop inapplicable braced bullets ~300, cut `Ticket-type handling` bullets for classes not in the run ~150 each, then condense titles), an explicit never-trim list (the METHOD stop-and-report bullet, the Safety push / PR / merge bullet, the commit-suffix rules, every flow tag), and an instruction to hand back a Story split rather than quietly print an over-cap block.
- `no-tests` is now a registered workspace label, raising the required set from seven to eight. It had become the routing key for `/tld-full-auto`, `/tld-goal-handoff`, and `/tld-setup` while remaining absent from the canonical "Required workspace labels" table, so `/campaign-init` never created it and `/campaign-test` never checked for it. On Linear, where labels must exist in the workspace before they can be applied, that meant the no-tests path was unreachable without hand-creating the label and nothing warned you; Jira was unaffected only because its labels are free-form strings. The label is registered as `no-tests` (`#6B7280`) with `build-only` documented as an accepted synonym rather than a second label, and the count and name list are updated in every reader: STANDARDS.md, `campaign-init`, `campaign-test` (including its Linear check list and Jira JQL audit), `campaign-validate`, README, docs/ADAPTERS.md, and docs/JIRA.md — which also gains a note that routing labels fail silently when mistyped. Follow-up to AS-4.
- Chore sweep from the 2026-07-28 flow review: `campaign-init` no longer calls Linear "the primary / recommended issue tracker" (Linear and Jira are both supported per LIMITATIONS.md; GitHub Issues / Other remain schema-accepted but unimplemented) and its Test Commands intro now lists all four slots (backend / frontend / landing / full); `tld-setup`'s description and intro are tracker-neutral ("pulls it from the issue tracker"); and step 1b in `tld-build`, `tld-write-tests`, and `tld-run-test` gains an identical **literal-skip guard** — a resolved command that is the literal `skip` or an `echo`-style SKIP placeholder is never executed (a placebo command only fakes a green run), is reported as "no runnable suite", and in `/tld-run-test` routes to the manual-QA-style verify path. (AS-11)
- `/tld-goal-handoff` now prints each handoff block with its own slash command *inside* the fenced code block, so one click on the copy button yields a message that can be pasted and sent with zero typing. Previously the skill put `/compact` and `/goal` in the prose label above each fence ("paste this into `/compact`"), leaving the copy button to hand back only the message body — the user had to retype the command every time, which defeated the point of a copy-paste handoff skill. The old "no second `/word` inside a `/compact` argument" rule was the likely cause: it read as *keep the slash command out of the block*, so it now says explicitly that the leading `/compact` is the command itself and belongs in the block. Adds a pre-print self-check table (both openings, slash-token count, untagged fences) gated on the question "if the user pastes this without typing another character, does it send correctly?", plus a rule keeping both fences untagged so a `bash` tag never turns a chat message into a runnable shell command.

## [v0.2.0] — 2026-05-03

### Added

- `/tld-release` skill — wraps the manual `RELEASING.md` procedure (CHANGELOG bump, release-branch PR, `gh release create`, marketplace auto-bump workflow watch) in one guided flow with hard stops at every destructive moment. Optional argument: `patch`, `minor`, `major`, or an explicit `vX.Y.Z`. Refuses to run when the working tree is dirty or when not on the default branch.
- `/tld-experience` skill — turns a lived conversation moment into a candidate skill on a new branch with the three house-style docs updated and a PR opened against `Jbrawner/tld-skills`. Runs `scripts/verify-block-alignment.py` before committing so embedded canonical blocks (sections that must match `STANDARDS.md` byte-for-byte) cannot drift.
- `/npc-partial` skill — content-ticket loop for skills/docs work with `skip` test commands. Runs `/tld-build` → HARD STOP for manual QA on the uncommitted diff → on approval commits and runs `/tld-next`. Skips `/tld-run-test` (no signal when the test command is `skip`) and lands the QA pause where it actually matters: between build and commit.
- `/npc-full` skill — uninterrupted variant of `/npc-partial` for content/doc tickets where the campaign test command is `skip`. Runs `/tld-build` → commit → `/tld-next` end-to-end with no QA pause between build and commit. Use when you trust the build and want the loop to keep moving; pair with `/npc-partial` when you want the diff-review stop.

- `docs/SKILL_REFERENCE.md` — removed as redundant. Its content (skill catalog, Standard Flow, Context Recovery) duplicates README.md and CONTRIBUTING.md. The README's "Standard Flow" section and CONTRIBUTING.md's skill catalog are now the canonical homes. `docs/ADAPTERS.md` stays — it's the only place the tracker-adapter contract lives.

## [v0.1.0] — 2026-04-29

First open-source release. Extracts the TLD (Test-Led Development) skills framework from a single private project ("mAIn Character") and makes it portable to other repositories.
